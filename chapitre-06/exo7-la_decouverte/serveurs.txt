Apparitions :
Le serveur "Serveur Test" figure trois fois dans la liste. Les trois lignes affichent la meme adresse textuelle, 172.172.172.172:172. Ce texte vient de NkAddress::ToString, qui formate les quatre octets de l'IP et le port. Ce n'est donc pas un artefact d'affichage : les trois adresses affichent les memes octets et le meme port.
Pourtant, Listen n'a pas fusionne les trois entrees. La deduplication compare les adresses completes par NkAddress::operator==, qui compare la famille, le port et les quatre octets de l'IP. Si les trois adresses etaient identiques, une seule entree resterait. Il y en a trois, donc les trois adresses sont differentes en interne, meme si ToString affiche le meme texte.
Je n'ai pas verifie quelle difference interne se cache derriere ce meme texte. C'est un point que je signale sans l'expliquer. La valeur affichee, 172.172.172.172:172, ne correspond ni a l'IP de la machine (172.29.9.155), ni au port de diffusion (7778). Il y a probablement une incoherence entre l'adresse source lue par RecvFrom et celle qui est stockee dans ServerInfo, mais je ne l'ai pas tracee.

Pourquoi :
Le nombre d'apparitions s'explique en lisant le code de NkDiscovery::Broadcast et de NkDiscovery::Listen dans NkLobby.cpp.
Dans Broadcast (ligne 924), un nouveau NkSocket est cree a chaque appel, avec NkAddress::Any(0). Le port 0 veut dire que l'OS choisit un port source libre, different a chaque appel. Le socket est ferme a la fin de l'appel.
Dans Listen (ligne 968), chaque paquet recu est associe a l'adresse source lue par RecvFrom, donc IP source plus port source. La deduplication compare les adresses completes par NkAddress::operator==, qui compare famille, port et octets IP.
Comme le port source change a chaque diffusion, chaque diffusion arrive avec une adresse source differente. Listen les voit donc comme des serveurs distincts et les ajoute tous a la liste. C'est ce qui explique les trois entrees.
Le serveur a diffuse trois fois pendant les six secondes d'ecoute du client : une diffusion au demarrage, puis une toutes les deux secondes. Le client a donc recu trois paquets, et la liste contient trois entrees. Avec une diffusion toutes les deux secondes et une ecoute de six secondes, on obtient trois apparitions. C'est exactement ce que l'experience montre.
Il reste une incoherence que je ne tranche pas : les trois lignes affichent la meme adresse textuelle alors que le raisonnement dit que les ports source sont differents. Le texte affiche ne reflete donc pas le port source reel. C'est un point que je signale sans l'expliquer, et qui pourrait venir de NkAddress::ToString ou de la maniere dont l'adresse source est stockee dans ServerInfo.
