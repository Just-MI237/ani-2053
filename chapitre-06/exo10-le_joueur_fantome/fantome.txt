Coupure : 16791, 16792, 16815, 16830. Quatre coupures mesurees en millisecondes, sur quatre essais successifs. J'ai tue le processus client par kill moins neuf, puis attendu que le serveur detecte le silence. Le delai est d'environ 16.8 secondes a chaque fois, tres stable. C'est le timeout d'inactivite du framework, kNkTimeoutMs = 10000 millisecondes dans NkNetDefines.h ligne 166, plus le temps de detection par cycle de UpdateConnections.

Fermeture propre : non mesuree. J'ai lance un client qui appelle Shutdown proprement apres dix messages, puis attendu quinze secondes cote serveur. Le serveur n'a pas declenche onPeerDisconnected pendant cette attente. Le FIN envoye par Shutdown n'a pas provoque la deconnexion cote serveur dans cette version du framework. Je le signale comme un defaut a verifier : soit le FIN n'est pas traite, soit il est perdu, soit le callback n'est pas cable correctement cote serveur. C'est un point que je n'ai pas pu trancher dans le temps disponible.

Raison : raison = Disconnected pour les quatre coupures. C'est la raison transmise par le framework dans NkConnectionManager::UpdateConnections, ligne 1318 de NkConnection.cpp. Le framework ne distingue pas une coupure brutale d'une fermeture propre a ce niveau. Dans les logs, chaque coupure est precedee d'un Timeout d'inactivite a NkConnection.cpp ligne 391, ce qui confirme que le serveur a detecte l'absence de messages, pas un FIN.

Table : avant coupure, la table contient un joueur. Pendant la coupure, le joueur reste dans la table jusqu'au timeout. Apres le timeout, le joueur est retire et la table revient a zero. Les logs complets montrent chaque ajout et chaque retrait. Extrait :
[CONNECT] joueur 4298217312260146839 ajoute a la table, thread = 126735091004992
[apres ajout] table joueurs (1)
[DISCONNECT] joueur 4298217312260146839 retire, raison = Disconnected, ecart = 16830 ms, thread = 126735091004992
[apres retrait] table joueurs (0)

Fil : le fil qui appelle onPeerDisconnected est le fil reseau du manager. Je l'ai verifie par la mesure. Le programme affiche le thread id dans le main et dans les callbacks. Sur un essai, le main affiche thread = 126735098234688, et les callbacks affichent thread = 126735091004992. Les deux valeurs sont differentes, donc onPeerDisconnected n'est pas appele depuis le fil principal. C'est le fil cree par StartServer a NkConnection.cpp ligne 935, qui execute NetThreadLoop ligne 1207, qui appelle UpdateConnections ligne 1219, qui detecte les connexions deconnectees et declenche le callback lignes 1317 et 1318.
Ce que cela impose a la table : elle est modifiee depuis un fil qui n'est pas celui du programme principal, donc toute lecture ou ecriture concurrente doit etre protegee. Mon programme utilise std::map sans mutex, ce qui est une course potentielle. Je le signale comme un defaut a corriger.
